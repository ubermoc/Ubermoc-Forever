HOW IT IS DONE, AND WHY (Ubermoc checked these on 2026-11-18; you re-verify every line you rely on)
1. Forever's plates are built from components (BLIZZ/Blizzard_NamePlates: Blizzard_NamePlates.xml, Blizzard_NamePlateUnitFrame.lua, Blizzard_NamePlateComponent.lua), not the old compact frames. On the plate's unit frame (plate.UnitFrame): HealthBarsContainer (xml line 103; holds healthBar, its border, selectedBorder, text, absorb textures), CastBarsContainer (173), WidgetContainer (180), RaidTargetFrame (186), ClassificationFrame (196), AurasFrame (217), PlayerLevelDiffFrame (259), LevelFrame (273), name (a FontString, 294, a child of the unit frame and NOT of the container), selectionHighlight (299, a texture with ignoreParentAlpha="true" and alpha .25), aggroHighlight (307).
2. Friendly players: the game has its own name-only mode. CVar nameplateShowOnlyNameForFriendlyPlayerUnits (Blizzard_NamePlateConstants.lua line 20); NamePlateUnitFrameMixin:UpdateShowOnlyName (Blizzard_NamePlateUnitFrame.lua 561-587) turns it on for friendly players, and the game then hides the bar, cast bar, auras, classification and raid target and clears the click area by itself. Our part is only SetCVar: no taint.
3. Enemies and friendly NPCs have no native mode. We hide the pieces with SetAlpha(0), a plain C call: no game Lua runs and nothing in the game is written. SetAlpha(0) on HealthBarsContainer hides everything inside it (no child there has ignoreParentAlpha, xml 103-172). selectionHighlight, aggroHighlight, LevelFrame and PlayerLevelDiffFrame get their own SetAlpha(0). Do not touch name, CastBarsContainer, WidgetContainer, RaidTargetFrame, ClassificationFrame or AurasFrame.
4. Nothing in BLIZZ/Blizzard_NamePlates calls SetAlpha (grep it), so no hook and no OnUpdate is needed. The game REUSES plate frames, so on every NAME_PLATE_UNIT_ADDED set the alpha both ways: hide the pieces when wanted, otherwise put each piece we hid back to the alpha it had BEFORE we hid it (selectionHighlight is .25 in the xml; putting back 1 would be a bug). Remember the original in a weak table: orig[piece] = GetAlpha() the first time only; if that is not a plain number (or is a secret value) use 1.
5. Do not read unit data. UnitHealth is always secret (BLIZZ/Blizzard_APIDocumentationGenerated/UnitDocumentation.lua 1528), UnitName and UnitClass are secret when identity is restricted (2491, 914), and any test or arithmetic on a secret raises an error. The one unit call allowed is UnitCanAttack("player", unit) (true = enemy, false = friendly), as Fade.lua applyPlates does. If the answer is a secret (issecretvalue) the kind is unknown and the plate is treated as not wanted (everything put back).
6. A plate can be forbidden to addons: C_NamePlate.GetNamePlateForUnit(unit) then returns nil (BLIZZ/Blizzard_APIDocumentationGenerated/NamePlateDocumentation.lua line 11, includeForbidden defaults to false). Then do nothing. Also check plate.UnitFrame exists and uf:IsForbidden() is not true before touching a piece, as Fade.lua does.

HARD RULES (each one came from a real error in this repo, LUA-WOW-GUIDE section 3)
- Never call a method of the game's nameplate pieces (SetShowOnlyName, UpdateShownState, UpdateAnchors, SetUnit, UpdateName, Show, Hide, SetShown ...). They run the game's code under our taint, and the game reads what they write.
- Never write a field on a game frame or table, not even uf.something = 1. Our state lives in our own weak-keyed tables: setmetatable({}, { __mode = "k" }).
- No hooksecurefunc, no replacing a game function, no SetPoint, ClearAllPoints, SetFont, SetText, GetText or GetTextColor on anything of the game's. No OnUpdate. No SetAttribute.
- SetCVar only for the one CVar above, only when InCombatLockdown() is false, and only by this rule: the first time we turn it on, keep the player's previous value in our saved settings (UF.DB().plates.prevOnlyName); when the option goes Off, give it back and clear it. In combat: set a pending flag and do it on PLAYER_REGEN_ENABLED.
- Every touch of a game frame inside pcall. Every game function or global that might not exist guarded.
- The new file is self-contained, about 120 lines. It uses nothing from Ubermoc UI.
- Lua 5.1 only (the game). No goto, no // or bit operators, no <const>. The offline test runs Lua 5.5 and will NOT catch these; tools/check_lua.py will.
